## ما نُفذ
- ثلاثة كيانات إضافية: LedgerAccount وJournalEntry وJournalLine، ومهاجرة 0006 لا تنشئ معاملات أو أرصدة تلقائية.
- 11 حسابًا تأسيسيًا تُنشأ بطلب مالك العقار، دون افتتاحيات مصطنعة.
- محرك نشر ذري مع قفل العقار، مدين/دائن بوحدات العملة الصغرى، مرجع مصدر وبصمة ومنع تكرار، وترقيم مستقل للعقار.
- منع تعديل/حذف القيود المنشورة عبر واجهات النموذج وQuerySet العادية. التصحيح بعكس كامل مرتبط بالأصل، مرة واحدة، مع تدقيق العملية.
- رفض بنود الحساب والحجز خارج العقار، المستخدم غير المالك، القيد غير المتوازن، المبالغ غير الصحيحة، المستقبل وخلط العملات.
- /api/ledger/ مقيد بعضوية المالك، مع ميزان افتتاحي وحركة وختامي ويومية وأستاذ؛ نهايات الفترات غير مشمولة.
- شاشة عربية «دفتر الأستاذ» للمالك: تهيئة، إدخال حتى أربعة بنود بالواجهة (المحرك حتى 100)، اعتماد صريح، عكس، فلاتر حساب وفترة وطباعة.

## حدود لا يجوز تجاهلها
1. هذا دفتر يدوي تأسيسي؛ لا تُرحّل إليه الحجوزات أو الفواتير أو سندات التشغيل تلقائيًا. تظهر هذه الملاحظة في الشاشة وAPI؛ لا يمثل ميزانًا شاملًا للمنشأة.
2. قيود قاعدة البيانات تفحص التفرد وتوازن مجموع رأس القيد وجانب البند. التوازن بين جميع البنود والعزل بينها يُفرض عبر خدمة النشر؛ لا توجد triggers أو RLS تمنع كتابة SQL مباشرة. وصول مشغل قاعدة البيانات خارج حدود API التطبيق.
3. لا افتتاحيات معتمدة، ولا إقفال فترات، ولا مطابقة بنك/صندوق، ولا ترحيل إرثي، ولا قائمة دخل شاملة. لا تُستنتج صحة المعالجة بمجرد توازن الميزان.
4. العرض يصل إلى 200 قيد في الفترة. الميزان مجمع كامل، لكن الرصيد الجاري للأستاذ لا يعرض عند بلوغ حد العرض؛ ضيّق الفترة.
5. صلاحية الدفتر للمالك فقط إلى حين تنفيذ دور المحاسب والصلاحيات التفصيلية.
6. لا ZATCA ولا تغيير لعلامة الفواتير التجريبية. لا تسعير اشتراكات نهائي ولا تكامل AI أو دفع ضمن هذه المرحلة.
7. التغيير في فرع مراجعة منفصل؛ لم تُطبق المهاجرة أو قيود مالية على Render أو بيانات تشغيل حقيقية.
