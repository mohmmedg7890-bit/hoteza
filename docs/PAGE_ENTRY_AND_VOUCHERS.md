# Page-based entry and unified voucher navigation

Guest, booking, unit, payment/refund/expense, invoice, checkout, contract terms and other operational entry/detail views now use a normal document section inside the application main area. They are not native dialogs and have no modal backdrop. The existing form/validation/service boundary is reused. The `showModal/close/open` compatibility methods refer only to this section, allowing existing form modules to keep working; confirmation still uses a separate native dialog with Yes/No buttons.

Every valid save validates/transforms its payload, then asks for Yes/No before sending. No keeps the page and entered values unchanged. Yes saves once using the existing idempotency key, closes the entry page and reloads shared state. Server errors keep the page open. The checkout document success view and booking-to-new-guest return flow are preserved. Each entry gets screen/record URL parameters; reload restores supported screens, and browser back returns to the prior list. Switching properties closes the previous entry and clears its booking draft.

The right sidebar and unified register expose receipts, refunds, expenses, departure settlements, invoices/credit/debit notes, ordinary operational vouchers, party vouchers and internal manual ledger entries. Ordinary and party views are classifications of existing documents, not new accounting transaction types. Internal entries are owner-only existing ledger data for the current month, with the ledger link for other periods. No fake new accounting engine or bank operation is introduced.

A new read-only tenant-scoped endpoint lists the latest 500 departure settlement snapshots, with an explicit total/truncation indicator. Expense vouchers now have tenant-scoped printable documents. The unified register reuses original document links and identifies each source. Guest/reservation terminology uses "page" instead of "file". Press feedback uses a contrasting purple wave, with reduced-motion support; no backdrop blur or page compositing animations are introduced.

Tests cover section markup, settlement/expense document isolation, and existing lifecycle/accounting behavior. Browser smoke verifies invalid forms, No preserves edits, Yes saves/returns, checkout, voucher register, desktop/mobile and tenant switching. No production financial records are created during tests.
