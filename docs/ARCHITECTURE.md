# بنية Hoteza

## مسار الطلب

HTML وJavaScript ← Django views ← pms.services.perform ← معاملة قاعدة البيانات ← تحديث الحالة والواجهة.

كل شاشة تقرأ من `/api/state/` لنفس المنشأة المختارة في جلسة المستخدم. لا يُقبل معرف منشأة من جسم طلب التعديل. اختيار المنشأة نفسه يتحقق من عضوية المستخدم. لا تعني صلاحية superuser تخطي فحص العضوية.

## الكيانات

| الكيان | العلاقات |
|---|---|
| Property | أصل الوحدات والنزلاء والحجوزات والعضويات والسجل |
| Membership | مستخدم + منشأة + دور؛ علاقة فريدة |
| Unit | منشأة، رقم فريد داخل المنشأة، نوع، طابق، سعة، سعر، نظافة، نشاط |
| Guest | منشأة، اسم، هاتف وبريد اختياريان |
| Reservation | نزيل، فترة نصف مفتوحة [الوصول، المغادرة)، حالة ومصدر |
| Allocation | حجز + وحدة + فترة، لحفظ النقل بين الوحدات |
| Block | وحدة + فترة صيانة + سبب |
| Charge | حجز + تاريخ خدمة + صافي وضريبة + فاتورة عند الإصدار |
| Payment | حجز + مبلغ موقع + طريقة ومرجع ومستخدم؛ الرد مبلغ سالب |
| Invoice | صورة JSON ثابتة وبنود ومجموع ومرجع إشعار التصحيح |
| Audit | مستخدم ومنشأة وعملية ومرجع دون حفظ كلمات المرور |
| Operation | مفتاح فريد لكل منشأة + بصمة الطلب + النتيجة |

## ضمانات وحدود

- يتم قفل سجل المنشأة قبل فحص التوافر وأي تعديل، بما يشمل الصيانة. هذا يقلل التوازي داخل المنشأة عمدًا لصالح الاتساق في نسخة التجربة.
- كل طرق الكتابة في التطبيق تمر عبر `perform`. لا يجوز إدخال حجوزات من SQL أو ORM خارج هذه الطبقة دون تطبيق القواعد؛ لا توجد حاليًا exclusion constraint خاصة بـPostgreSQL.
- التسكين يتطلب وحدة نظيفة، مع منع تسليم وحدة لنزيل آخر بينما نزيلها السابق متأخر عن المغادرة.
- النقل في اليوم نفسه يسجل الوحدة السابقة والجديدة في سجل التدقيق؛ تخصيص الوحدة مدته باليوم. نقل متعدد داخل اليوم لا يقدم توزيع تكلفة بالساعات.
- الفواتير صور ثابتة لا تتغير عند تعديل ملف النزيل أو المنشأة. لا توجد API لتحرير فاتورة صادرة.
- الإيراد محسوب بتاريخ الخدمة والمقبوض بتاريخ الدفع. الأسعار الأساسية قبل الضريبة.
- التعديل المالي العام يُحتسب بتاريخ التصحيح؛ لا يوزع تلقائيًا على أنواع الإيراد، ولذلك ينبغي تفسير ADR بعد أي تصحيح يدوي واسع. إلغاء الليالي في المغادرة المبكرة يعكس إيراد الليالي الملغاة.
- تجميع الحالة الحالي يناسب تجربة صغيرة؛ يلزم ترقيم صفحات واستعلامات محسّنة واختبار حمل قبل سنوات من البيانات أو أعداد كبيرة من المنشآت.

## خريطة الواجهة

Dashboard / Calendar / Reservations / Today / Units / Guests / Housekeeping / Payments / Invoices / Balances / Reports / Users / Settings / Audit / Profile.

ملف الحجز مركزي: يظهر التخصيص والرسوم والدفعات والفواتير وأزرار العمليات. الروابط إلى المستندات مفحوصة حسب منشأة الجلسة. ملفات CSV وExcel تحيد صيغ الخلايا القادمة من مدخلات المستخدم.
