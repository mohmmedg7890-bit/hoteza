# Hoteza — نظام تشغيل منشآت الضيافة

تطبيق مستقل بـ Python / Django وقوالب HTML وCSS وJavaScript عربية RTL. لا يعتمد على WordPress ولا على SyncStay.

**حالة الإصدار: نسخة تجريبية محلية قابلة للتشغيل. ليست اعتمادًا للإطلاق التجاري أو للفوترة الإلكترونية.**

## تشغيل محلي

على Windows بعد تثبيت Python 3.12، افتح PowerShell داخل مجلد المشروع وشغّل `powershell -ExecutionPolicy Bypass -File run-local.ps1`. يثبت المتطلبات وينشئ بيانات العرض عند أول تشغيل ويطبع كلمة مرور عشوائية، ثم يفتح خادمًا محليًا فقط. لا يستخدم للاستضافة العامة. بقية الخطوات اليدوية أدناه.

Python 3.12، ثم:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DEBUG=1
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

في Windows: استخدم `.venv\Scripts\Activate.ps1` و`$env:DEBUG="1"` بدل تفعيل Linux. أمر `seed_demo` ينشئ منشأتين و30 وحدة و12 حجزًا ببيانات وهمية ويطبع كلمة مرور عشوائية مرة واحدة. يرفض الكتابة فوق بيانات قائمة. لا تنفذه في الإنتاج.

بديل لبيانات العرض: `python manage.py createsuperuser`، ثم تسجيل الدخول وإعداد منشأة من `/setup/` وإضافة الوحدات والمستخدمين من الواجهة.

## المنفذ

- تسجيل الدخول والاستعادة عبر البريد بعد إعداد SMTP، وخروج POST محمي بـCSRF.
- عضوية المنشأة وصلاحيات مالك واستقبال والتحقق من العلاقات على الخادم.
- وحدات وطوابق وأنواع وسعة وأسعار وأرشفة، مع تنظيف وصيانة بفترات.
- حجز وتعديل وإلغاء وتسكين وتمديد ونقل ومغادرة، وحساب نزيل موحد.
- حفظ الأموال بوحدات العملة الصغرى الصحيحة، والتقريب الضريبي لكل بند.
- منع التعارض وقفل جميع الكتابات للمنشأة داخل معاملة. SQLite للتطوير يستخدم BEGIN IMMEDIATE وPostgreSQL يستخدم قفل سجل المنشأة.
- مفاتيح عمليات لمنع تكرار الحجز أو التحصيل، مع رفض إعادة استخدام المفتاح لطلب مختلف.
- سندات قبض ورد مبلغ، وفاتورة تجريبية ثابتة وإشعارات تصحيح مرتبطة، ومغادرة مبكرة محسوبة.
- تقارير الفترة والإشغال والإيراد والتحصيل وADR وRevPAR، وتقويم 14 يومًا.
- معاينة وطباعة وتصدير حقيقي PDF / XLSX / DOCX / CSV / PNG / JSON بحسب التقرير والمستند.
- سجل تدقيق، وانتهاء فترة التجربة يمنع الكتابة مع استمرار القراءة والتصدير.
- نسخ منطقي كامل واستعادة إلى قاعدة فارغة بأوامر الإدارة.

## الاختبار

```bash
DEBUG=1 python manage.py test pms
DEBUG=1 TEST_DB_PATH=/tmp/hoteza-race.sqlite3 python manage.py test pms.tests.ConcurrencyCase --noinput
node --check static/app.js
```

اختبار SQLite في الذاكرة يتجاوز اختبار التزامن؛ الأمر الثاني يستخدم قاعدة ملفية. مسار CI يفحص PostgreSQL الحقيقي. راجع `docs/QA.md` للنتائج الفعلية، و`docs/RELEASE_GATES.md` للفجوات قبل البيع.

## ملفات التوثيق

- `docs/ARCHITECTURE.md`: البيانات والربط والقواعد.
- `docs/OPERATIONS.md`: دورة المستخدم والحسابات.
- `docs/DEPLOYMENT.md`: التشغيل على استضافة مستقلة والنسخ والاستعادة.
- `docs/MARKETING.md`: خطة تجربة وإطلاق تسويقي قابلة للقياس.
- `docs/RELEASE_GATES.md`: حدود هذه النسخة وموانع الإطلاق.

لا توجد كلمات مرور أو مفاتيح أو بيانات نزلاء حقيقية داخل المستودع. الاشتراكات حاليًا تُدار يدويًا بواسطة مشغّل النظام؛ لا توجد بوابة تحصيل اشتراكات أو مزامنة منصات خارجية.
